# SMTP Mail-Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send password-reset email through a remote, authenticated SMTP relay with STARTTLS/TLS, while keeping mail disabled by default and preserving the existing `password_reset_token_in_response` behavior.

**Architecture:** Add a `microwave-mail` crate with a `Mailer` trait, a `lettre`-backed SMTP implementation, and a bounded in-process dispatcher. Wire one mailer into `AppState`/`OAuthState`, add `[mail]` and `server.public_url` configuration, enforce a reset-token TTL, and send the reset link from `/id/password-reset`.

**Tech Stack:** Rust 1.94, Tokio, Axum, `lettre` 0.11 (rustls), Serde/TOML, `thiserror`, existing SQLite/PostgreSQL store abstraction.

**Spec:** `docs/superpowers/specs/2026-10-26-smtp-mail-design.md`

## Global Constraints

- Mail is **disabled by default**: `mail.enabled = false` must not change startup, tests, or endpoint behavior.
- Remote SMTP with authentication is the production path; SMTP AUTH over `security = "none"` is rejected.
- Never log, serialize into backups, or include in `Debug` output: the SMTP password or password-reset token.
- `auth.password_reset_token_in_response` remains effective **independently of mail**: when `true`, the response includes `reset_url` even if mail was sent; when `false` (default), it must not.
- `server.public_url` is required when mail is enabled. It must be an absolute `http`/`https` origin with no path, query, or fragment. `https` is required except for `localhost`, `127.0.0.1`, and `[::1]`, where `http` is accepted.
- No durable outbox, retries, or built-in rate limiter in this slice. The dispatcher is bounded; overflow is logged and dropped.
- The reset token TTL is `auth.password_reset_ttl_seconds` (default `3600`) and is enforced on lookup and consumption.
- Every task ends with `cargo fmt --all`, targeted tests, and clippy `-D warnings` where applicable.

## Review Focus

These are the failure modes most likely to bite an operator, in priority order:

1. **Credential leakage:** SMTP password appears in `Debug`, serialized config/backup, logs, or error text.
2. **Plaintext authentication:** credentials sent over `security = "none"`.
3. **Unavailable mail changes the HTTP contract:** SMTP failure, queue overflow, or a missing recipient turns password reset into a 5xx or leaks account existence.
4. **Broken or attacker-controlled reset links:** missing/invalid `server.public_url`, path prefixes, trailing slashes, or Host-header-derived URLs.
5. **Flag regression:** reset token is missing when `password_reset_token_in_response = true`, exposed when `false`, or an expired token is accepted.

Each line is pinned to a test in the task that owns the behavior.
