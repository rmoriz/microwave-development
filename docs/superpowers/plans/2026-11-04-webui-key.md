# Optional Dedicated WebUI Keypair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in, store-backed WebUI keypair so `X-Ops-Request-Source: web` impersonation trusts a dedicated key instead of the superuser key.

**Architecture:** `auth.webui_key` enables a keypair stored in `kvpair` under `secret:webui:*` and materialized to `webui_priv.pem` / `webui_pub.pem`. Bootstrap resolves the key once at startup (store → import file → generate) and hands the public PEM to `AppState`; the signed-request middleware uses it only in the existing web-impersonation branch.

**Tech Stack:** Rust, axum, rusqlite/PostgreSQL metadata store, `microwave-crypto` (RSA-2048 PEM), clap-based `microwave-ctl`.

**Spec:** `docs/superpowers/specs/2026-11-04-webui-key-design.md`

## Global Constraints

- Default `auth.webui_key = false`; every behavior without the switch stays byte-for-byte as today.
- The metadata store is the source of truth. The files are materialized on every start; a divergent file is overwritten.
- RSA-2048. Private key PKCS#8 PEM, public key SPKI PEM. Imports accept PKCS#1 and PKCS#8 private PEMs.
- The private key must never appear in logs, `microwave-server config`, `_status`, metrics, error messages, or CLI output other than `show-secret`. Log only the public-key fingerprint.
- Materialization is atomic: sibling temp file, mode set, rename. Private `0600`, public `0644`, newly created parent directories `0700`.
- Both SQLite and PostgreSQL must work. First-start races use `MetadataStore::set_secret_if_absent`.
- When `auth.webui_key = true` and `AppState.webui_key` is `None`, web impersonation fails closed with 401. Never fall back to the superuser key.
- `webui` lives in `EXTRA_CREDENTIALS`, not `KNOWN_CREDENTIALS`. `show-service-credentials` and `rotate-all` must not expose or rotate it.
- No new crate dependencies.

## Review Focus

1. Enabling the switch while an invalid `webui_priv.pem` exists: startup must fail with an actionable error, not regenerate silently.
2. Two replicas starting at once: one retained private key, matching public key, identical materialized files.
3. `webui_key = false` with a stale dedicated key file present: superuser impersonation still works and the file is untouched.
4. Custom `webui_key_path` whose parent directory does not exist: directories are created `0700`, files `0600`/`0644`, and there is no fallback to `data_dir`.
5. `set-secret webui private_key` with PKCS#1 input: accepted and the public half derived (Task 2 pins the shared helper against PKCS#1); garbage input: rejected before either secret is written (Task 5).

```rust
/// Derive the SPKI public PEM that matches a PKCS#1 or PKCS#8 private PEM.
pub fn public_key_pem_from_private(private_pem: &str) -> Result<String, CryptoError> {
    parse_private_key_pem(private_pem)?
```

`ensure_webui_key` algorithm:

1. Return `Ok(None)` immediately when `!config.auth.webui_key`.
2. `let private_path = webui_private_key_path(config);`
3. Read `store.get_secret(WEBUI_SECRET_GROUP, WEBUI_PRIVATE_KEY_NAME).await?`.
   - If present, use it and label the source `"secret:webui:private_key"`.
   - If absent, use the import source at `private_path` when `is_file()`, else `generate_rsa_keypair()?.0`. Label the source with the path, or `"generated"`.
4. Parse the candidate with `parse_private_key_pem`. On failure return an error string that names the source and ends with: ``run `microwave-ctl rotate webui` to replace the pair``.
5. Retain with `store.set_secret_if_absent(WEBUI_SECRET_GROUP, WEBUI_PRIVATE_KEY_NAME, &candidate).await?`; the returned value is authoritative.
6. Derive `public_pem = public_key_pem_from_private(&retained)?` and `store.set_secret(WEBUI_SECRET_GROUP, WEBUI_PUBLIC_KEY_NAME, &public_pem).await?`. When `retained != candidate` (another replica won the race), run the same `parse_private_key_pem` validation on `retained` first so an invalid stored key still gets the actionable message.
7. Materialize: `write_materialized_file(&private_path, &retained, 0o600)?` and `write_materialized_file(&private_path.with_file_name("webui_pub.pem"), &public_pem, 0o644)?`. If the file existed with different contents, log `tracing::info!(path = %private_path.display(), "materialized the webui private key from the metadata store")`.
8. Log `tracing::info!(fingerprint = %public_key_fingerprint(&public_pem)?, "webui keypair is enabled")`.
9. Return `Ok(Some(public_pem))`.

Add the atomic writer:

```rust
fn write_materialized_file(path: &Path, contents: &str, mode: u32) -> Result<(), std::io::Error> {
    let parent = path.parent().unwrap_or_else(|| Path::new("."));
    create_private_dirs(parent)?;
    let name = path.file_name().ok_or_else(|| {
        std::io::Error::new(std::io::ErrorKind::InvalidInput, "path has no file name")
    })?;
    let temp = parent.join(format!(
        ".{}.tmp-{}",
        name.to_string_lossy(),
        Uuid::new_v4().simple()
    ));
    let mut options = std::fs::OpenOptions::new();
    options.write(true).create_new(true);
    #[cfg(unix)]
    {
        use std::os::unix::fs::OpenOptionsExt;
        options.mode(mode);
    }
    let mut file = options.open(&temp)?;
    use std::io::Write;
    file.write_all(contents.as_bytes())?;
    file.sync_all()?;
    drop(file);
    std::fs::rename(&temp, path)?;
    Ok(())
```

```rust
async fn impersonated_principal_with_key(
    state: &crate::AppState,
    org: Option<&microwave_store::Org>,
    user_id: &str,
    auth_headers: &microwave_crypto::AuthHeaders,
    canonical: &microwave_crypto::CanonicalRequest<'_>,
    verification_key: &str,
    key_name: &str,
) -> Result<Option<(microwave_store::Principal, String)>, ApiError> {
    if microwave_crypto::verify_request(verification_key, auth_headers, canonical).is_err() {
        return Ok(None);
    }

        .store
        .find_user(user_id)

        .map_err(ApiError::from)?

        return Ok(None);

        actor_id: user.id,
        authz_id: user.authz_id,
        name: user.username,
        actor_type: ActorType::User,
        org_id: org.map(|org| org.id.clone()),
    };
```
